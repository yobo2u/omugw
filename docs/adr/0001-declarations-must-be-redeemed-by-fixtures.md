# 降级矩阵的声明必须由 fixture 兑现

M0 结束时降级矩阵登记了 14 条路径的全部处置，而 `internal/` 下没有 codec、
transport、job 任何一个包——矩阵 100% 描述的是意图，不是现实，且没有任何机制
能发现这件事。`TestPhase1IsComplete` 只检查「每格都表态了」，不检查「表的态是
真的」。因此路径增加 `Implemented` 标记，默认为 `PLANNED`；运行时对 `PLANNED`
路径的请求明确报错而非静默失败；要把一条路径转正，门槛是**端到端 fixture 通过**，
另外 16 个 `DEGRADE` 与 4 个 `EMULATE` 格子各自需要专门的 fixture——有损转换正是
bug 藏身之处，`PASSTHROUGH` 格子由路径级 fixture 顺带覆盖即可。

## Considered Options

- **实现侧注册表**：每个 codec 登记自己实现了哪些能力，启动时与矩阵比对。
  否决理由是登记本身也是自我声明，挡不住「登记了但实际没实现」——把一个自我
  声明用另一个自我声明去校验，等于没校验。
- **只加标记，不设转正门槛**：最轻，但转正完全靠自觉。矩阵的全部价值在于它
  可信；一个可以随手翻成 `true` 的布尔值会慢慢腐蚀这份可信。
- **只要 fixture 覆盖率，不加标记**：证据最硬，但 M1 完成前 CI 会一直红，
  失去信号作用。

## Consequences

`PLANNED` 的语义被定为「计划要做」而非「设计完成待实现」，因此 `openai.audio`
与 `openai.images` 也补齐可表达性声明并注册进矩阵。代价是 19 条路径里有 16 条
标着规划中——文档读起来会像个空壳。这是诚实的代价，不是缺陷。
