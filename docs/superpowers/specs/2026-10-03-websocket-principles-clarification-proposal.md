## 2.2建议替换的边界

同协议且同契约的应用消息可以旁路IR原样保全；同契约要求版本、字段语义、取值、
默认值、更新规则及有效编码参数一致，不把协议名称相似、历史MarkHomogeneous或
相同事件名作为跨协议等价的证明。保全消息类型、负载及各方向顺序，不承诺网络帧
一致；握手凭据（含承载密钥的子协议token）须清洗替换，不支持的形态显式拒绝。
OpenAI Realtime→DashScope Realtime不获笼统快通道授权，跨协议未知语义须可见地失败。

原生直通的独立验收包括双向负载保全、握手凭据替换、原错误与关闭、计量观测
及fixture能力覆盖表。没有转换器的同协议路径不为对照制造虚假的重编码器。
当相应跨协议转换路径可用时，对已建模语义用相同上游轨迹独立验证转换预期；
不透明字段只在同契约侧验证保全。原生保全通过与转换对照通过分别记录。

这项改动使A包可独立验证，不能据此降低C包的presence/配置确认/cancel/truncate/DSP标准。
整门兑现仍需端点fixture和能力证据映射；上游模型支持范围与网关保全范围分开。

## 2.4建议补充

HTTP首字节由下游tracked.wrote判定；WS从Hijack/开始写101进入不可重试状态，
当前协调器在进入Accept前即标记committed，Accept失败或交接错误也不可重拨。
Realtime先完成上游握手并预读、校验session.created，再Accept下游并交付首事件。
Inference只需先完成上游握手再Accept，不能在下游101前等task-started；该事件依赖
客户端在101后提交run-task，预先等待会死锁。会话中断只将未结或不可知用量标
unavailable，已有终态权威usage保留，不因后续中断清零或降级。

## 2.7建议补充

HTTP保留connect < first_byte ≤ total与idle ≤ total的四层关系；共享配置校验不变。
WS不套HTTP total；connect限TCP/TLS，first_byte为自入站处理开始、跨凭据与Provider
候选共用的不可重置绝对期限，覆盖上游握手、协议要求的首事件与下游101写入和交付。
候选切换、ping/pong或阶段切换不能续时；Inference不在升级前等待task-started。
成功后解除握手期限，切到idle与有限写期限。心跳只检验传输存活，不替代业务终态
或任务超时。
