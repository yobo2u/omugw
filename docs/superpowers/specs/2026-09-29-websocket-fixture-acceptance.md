# WS fixture 回放机制验收清单

**状态：修订稿（2026-09-30），测试尚未实现。**
对应 [设计稿](2026-09-29-websocket-fixture-design.md)。
本表验证的是举证工具本身，不能替代具体协议能力的真实来源证据。

## P0：防止错误实现被判为通过

| 用例 | 操作 | 应有结果 |
|---|---|---|
| 自证录制 | 「网关 → 上游」的预期来源标签不是 `upstream-accepted`，或取自网关输出 | 加载失败，点名观测点 |
| 握手路径错误 | 相同模型，打错上游路径 | 失败，定位握手路径 |
| realtime 模型错误 | 握手 query 漏掉或改错 model | 失败，不匹配另一份 fixture |
| inference 模型错误 | run-task 的 `payload.model` 改错 | 失败；不去检查握手 query |
| 鉴权替换 | 两端使用不同测试凭据 | 上游只见出站凭据，下游凭据未泄漏 |
| 子协议凭据 | key 放在子协议 token | 凭据 token 清除，协议 token 保留 |
| 改写名单内 | 同契约路径按名单改写 `model` | 通过 |
| 改写名单外 | 同契约路径改动名单外的任一字段 | 失败，点名字段路径 |
| 不透明字段 | 同契约路径加未知固定哨兵字段 | 原样保留，不因未建模而消失 |
| 请求静默丢字段 | 网关省略预期的配置值 | 上游观测点断言失败 |
| presence 三分 | 依次省略、null、false/0/空集合 | 按契约分别比较，不能合并 |
| 采样率错配 | 请求 24k，回显 16k | 转换侧不能判为确认 24k |
| 异构音频 | 网关输出采样率或长度错误；频谱超出 #8 容差 | 失败；容差内通过 |
| 异构响应错信封 | 正确内容装进另一协议事件 | 客户端观测点失败 |
| 多余消息 | 上游收到未预期的命令 | 立即失败，不默默消费 |
| 缺失消息 | 网关漏发末尾命令，连接关闭 | 失败并指明未消费节点 |
| 半截成功 | 未完成 response，收到正常 close | 不能冒充正常业务完成 |
| 动态 ID 错绑 | tool result 引用另一 call ID | 失败，归一化不能掩盖错绑 |
| 实体 ID 混用 | session ID 被当作 response ID | 失败，命名空间隔离 |
| 负载截断 | binary 或 base64 音频缺尾部 | 逐字节/长度断言失败 |
| 重复用量 | 同笔终态报告两次 | 对应来源与 ID 的量只入账一次 |
| 中断用量 | 前一轮已结算、当前轮断连 | 保留前一轮，当前笔不可知 |
| 101 前失败 | 上游 401/429/断连 | 下游尚未升级，允许合法 failover |
| 部分 101 | 下游升级响应部分写出后失败 | 不换上游、不再写 HTTP 错误信封 |

## P1：门禁对接、可重放与资源边界

| 用例 | 操作 | 应有结果 |
|---|---|---|
| 有损格子缺文件 | 异构 realtime 路径缺 `audio_input.json` 或 `parallel_tool_calls.json` | `checkRouteFixtures` 失败 |
| path 带 query | `request.path` 含 `?model=` | 端点对账失败，提示 query 另存 |
| 门归属错绑 | WS 门 Redeem 到非归属协议的路径 | Build 失败 |
| 源证据缺失 | synthetic fixture 声称云端能力已证实 | 投放证据校验失败 |
| 数据来源变更 | 替换音频内容但未改摘要 | 校验失败 |
| 因果反转 | 未收 update 就发送对应确认 | 回放器拒绝非法轨迹 |
| 依赖环 | A 等 B、B 等 A | 加载失败，不进入等待 |
| 悬空引用 | after 指向不存在的节点 | 加载失败，点名节点 |
| 合法交错 | usage 与配置确认交换跨方向到达次序 | 依赖均满足时通过 |
| 多调度 | 就绪集合曾多于一条的 fixture | 至少两种 seed 均通过相同断言 |
| 单一顺序 | 依赖严格串行的 fixture | 报告可行顺序数为 1，不强行凑第二种 |
| 固定调度 | 重复执行相同 seed | 输出一致，无墙上时钟依赖 |
| inference 多任务 | 同一连接顺序跑两个任务 | `task_id` 分别绑定，互不串号 |
| task-failed 后复用 | 任务失败后在同一连接再发 run-task | 不当作合法回放 |
| run-task 顺序 | task-started 前发送音频 | 不当作合法回放 |
| 消息数上限 | 超过配置的轨迹节点数 | 拒绝，不无限积累 |
| 负载预算 | 少量节点承载超限音频 | 按字节预算拒绝 |
| ID 绑定上限 | 多个小消息创建过量实体 | 拒绝，不无限增长映射 |
| 等待上限 | 缺终态且连接一直未断 | watchdog 失败，不能挂住 CI |
| 失败收尾 | 一侧断开，另一侧阻塞写 | 有限时间内关闭两端并收回 goroutine |
| query 去敏 | 查询串含 token 或 userinfo | 落盘失败或按明确规则去敏，日志不含原值 |
| 消息内隐私 | 样本含未批准的隐私/凭据字段 | 候选录制不得入库 |
| 替换名单过宽 | 通配忽略 usage/采样率/内容 | 校验拒绝该匹配规则 |
| HTTP/SSE 兼容 | 运行既有所有 fixture | 原有请求校验与 golden 不退化 |

## P2：诊断质量

- 失败定位到观测点、节点与字段路径，不整段打印音频或敏感信封。
- 一份轨迹可以关联多个能力断言，但每项投放有可追踪的具体节点证据。
- 记录层 schema 版本不识别时明确失败，不能按另一版格式静默读取。

## 与真实能力验收的分工

上述边界用小体积脚本化负例即可证明，不要求每种失败都去攻击真实上游。
真实录制负责证明模型与端点契约可用，DSP 合成信号负责频谱/抗混叠，短语音
样本负责语音场景。三种测试证据分别保留来源、样本与断言，不能互相顶替。
