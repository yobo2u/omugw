# Domain docs

本仓库采用 single-context 域文档布局：

- `CONTEXT.md`：全仓唯一术语表，只记录领域词义、边界与应避免的别名。
- `docs/adr/`：系统级架构决策，记录难以逆转、缺少上下文会令人意外、且确实经过
  取舍的决定。

## 消费规则

1. 开始设计、实现或审查前，先读根 `CONTEXT.md` 与相关 ADR，再读
   `docs/architecture/principles.md`。
2. 讨论中出现含混词时，先用 `CONTEXT.md` 的既有词义校正；只有词义真正变化时才更新
   术语表。
3. `CONTEXT.md` 不存实现细节、计划、状态或临时结论。路径、函数与文件位置属于计划或
   知识库，不属于术语表。
4. 只有同时满足「难逆」「无上下文会意外」「存在真实取舍」三项时才新增 ADR；普通
   实现选择留在设计文档。
5. 术语或决策一旦在讨论中定稿，立即更新对应文档，不在会话末尾批量补写。

如果以后拆成多个真正独立的业务上下文，再引入根 `CONTEXT-MAP.md` 与上下文局部的
`CONTEXT.md`；当前包目录只是实现模块，不构成多上下文。
